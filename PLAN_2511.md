## 3. Resumen Diario / Puente de Medición — **FÓRMULAS INVERTIDAS (CRÍTICO)**

### Estado actual (L1930-1988 `operativa.ts`)

```typescript
// MAL: Ingreso = gncOpening (suma aperturas mangueras = cierre turno anterior)
const gncIngreso = act?.gncOpening ?? 0;

// BIEN: Merma = puenteEntrante - puenteSaliente (ya correcto en L1937)
const gncMermasExcedencias = sr ? sr.puenteEntrante - sr.puenteSaliente : 0;

// MAL: % usa denominador erróneo (gncIngreso en vez de bridge diff)
const gncPorcentaje = gncIngreso > 0 ? ((gncMermasExcedencias / gncIngreso) * 100) : 0;

// TOTALES: suma todo (L1967-1976) PERO % total = weighted average (L1987-1988)
const totalsPorcentaje = totals.gncIngreso > 0 
  ? (totals.gncMermasExcedencias / totals.gncIngreso) * 100 
  : 0;
```

### Lo que pide el cliente

| Fila | Fórmula correcta |
|------|------------------|
| **Ingreso GNC (m³)** | `puenteEntrante - puenteSaliente` (lo que pasó por el medidor) |
| **Venta GNC (m³)** | `gncVolume` (suma closing-opening 6 mangueras) — **ya correcto** |
| **Mermas/Excedencias (m³)** | `Ingreso - Venta` = `(puenteEntrante - puenteSaliente) - gncVolume` |
| **% Mermas/Excedencias** | `Mermas / Ingreso * 100` |
| **Totales (pie)** | **% se SUMA** (no weighted average). Ingreso, Venta, Mermas se suman. |
| **Filas en tabla** | Solo 2 filas: **Mermas/Excedencias (m³)** y **% Mermas/Excedencias** (eliminar duplicada). |

### Datos necesarios
- `shiftReports` ya tiene `puenteEntrante` y `puenteSaliente` (L637-638).
- `dailyActivities` **NO** tiene campos de puente. El upsert desde rendición (L3260-3288) solo guarda `gncOpening/Closing/Volume/Sales`.
- **Opción**: En resumen diario, leer `puenteEntrante/Saliente` directo de `shiftReportsData` (ya se hace en L1932, L1937). No hace falta migración BD si solo se usa en vista.

## 8. Turno Noche — **LÓGICA DE FECHAS (DETALLE TÉCNICO)**

- `shiftReports` tiene `shiftStart`/`shiftEnd` (timestamp_ms) + CHECK `shift_end > shift_start` (L656).
- Form rendición envía `shift_start`/`shift_end` calculados en frontend (L3022-3030 aprox).
- **Problema**: Turno noche 22:00 día X → 06:00 día X+1 ⇒ `shiftEnd < shiftStart` en timestamps ⇒ CHECK falla.
- **Solución preferida (cliente)**: Solo `fecha` (inicio). Backend infiere:
  - Mañana: 06:00-14:00 mismo día
  - Tarde: 14:00-22:00 mismo día
  - Noche: 22:00 día X → 06:00 día X+1
- Quitar campos `shift_start`/`shift_end` del form. Calcular en POST.
